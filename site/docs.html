Install安装

Node.js 20 or newer runs the MCP server and the CLI. Clone the repository, install and build: 运行 MCP 服务器和 CLI 需要 Node.js 20 或更新版本。克隆仓库后安装并构建： 

npm install
npm run build        # outputs packages/mcp-server/dist

To try it in Claude Code for one session, without touching global config: 在 Claude Code 里只为当前会话试用，不改全局配置： 

claude --plugin-dir /path/to/ai-ad-monetization

For a generic MCP client, point it at the built server entry: 其他 MCP 客户端把配置指向构建产物即可： 

{
  "mcpServers": {
    "ad-monetization": {
      "command": "node",
      "args": ["/path/to/ai-ad-monetization/packages/mcp-server/dist/index.js"]
    }
  }
}

To build the app you need Flutter 3.38.1 or newer, Xcode for iOS, and JDK 17 with Android SDK 36 for Android. If a tool is missing, that build step is skipped and named, never counted as passed. 构建应用需要 Flutter 3.38.1 或更新版本，iOS 需要 Xcode，Android 需要 JDK 17 和 Android SDK 36。缺哪个工具，对应的构建步骤就显示 skipped 并写明原因，不会算成通过。

Ask an agent交给 Agent

Say what you want in your own words, for example: 用你自己的话说出需求即可，例如： 

Add a banner, an interstitial and a rewarded ad to this Flutter app.
Show me the plan before you write.

The skill then walks the sequence analyze, recommend, plan, confirm, apply, validate, verify. Each step shows its result before the next one runs. Skill 会按 analyze、recommend、plan、confirm、apply、validate、verify 的顺序推进，每一步都会先给你看结果。

The write step is two-phase. First a plan with diffs and a plan hash; nothing touches disk. Applying needs confirm: true and the expectedPlanHash from the plan, so a changed project is refused instead of half-written. 写入分两步。第一步只返回计划和 diff 以及计划哈希，不写盘；执行 apply 必须带 confirm: true 和计划返回的 expectedPlanHash，工程一旦被改动就会拒绝，避免写一半。

generate_ad_integrationmode: apply confirm: trueexpectedPlanHash: <planHash>

Generated code lives under lib/ads, plus one test that plays a test ad on a device. Your own code is not rewritten: 生成的代码放在 lib/ads 下，另外还有一个在设备上试播测试广告的测试。你自己的代码不会被改写：

File文件Role作用

The interstitial and rewarded controllers expose lastLoadError with the most recent load failure. A settings entry can call showPrivacyOptionsAndRetry() so an EEA user can change consent later. Real IDs are injected at build time, e.g. --dart-define=ADMOB_ANDROID_BANNER_ID=ca-app-pub-xxxx/yyyy, without editing source. 插屏和激励控制器提供 lastLoadError，可以读到最近一次加载失败。设置页可以调用 showPrivacyOptionsAndRetry()，让 EEA 用户之后随时修改同意状态。真实 ID 在构建时注入，例如 --dart-define=ADMOB_ANDROID_BANNER_ID=ca-app-pub-xxxx/yyyy，不需要改源码。

Verify验证

Three levels, reported separately: static config checks, platform builds, and test ads actually loading on a device you name. A missing toolchain makes that step skipped, and skipped is never passed. 三级分开报告：静态配置检查、平台构建、以及在你指定的设备上真实加载测试广告。缺工具链的步骤是 skipped，而跳过永远不算通过。 

node packages/mcp-server/dist/cli.js verify <project> \
  --levels static,build,runtime --devices <id> --show-fullscreen

Exit codes: 0 means no requested level failed, 1 means a level failed, 3 means every requested level was skipped. 退出码：0 表示请求的级别没有失败；1 表示有级别失败；3 表示所有请求的级别都被跳过。
